# rustprop Implementation Plan

Phased, checkbox-tracked plan for porting CoolProp v8.0.0 to pure Rust. Every step ends in a
`→ verify:` clause — a step without a passing verification is not done. Work the phases in order;
within a phase, steps are ordered by dependency.

**Working rules** (binding for every step):

1. Follow `.claude/skills/karpathy-guidelines/SKILL.md`: surface assumptions before coding;
   minimum code that solves the step (no speculative abstractions or configurability); surgical
   diffs; every task framed as a verifiable goal.
2. Fidelity mandate from CLAUDE.md: same algorithms, same data as upstream v8.0.0. When the port
   deviates for language reasons (e.g., no exceptions), record it in the Decisions log below.
3. A step is complete only when: its verify clause passes, `cargo fmt --all --check`,
   `cargo clippy --workspace --all-targets --all-features -- -D warnings`,
   `cargo test --workspace --all-features`, and the wasm facade build are all green locally.
   Tick the checkbox and update the Decisions log in the same commit as the work. Push; CI must
   stay green.
4. At each **phase gate**: update CLAUDE.md's Status section, then commit.

## Verification oracles

- **Upstream goldens (primary)**: reference values generated by running the real CoolProp 8.0.0
  (Python wrapper, `pip install CoolProp==8.0.0`) on this machine (Python 3.12.3 verified
  available). Generator scripts live in `tools/golden-gen/`; fixtures are committed under
  `tests/golden/fixtures/` and never edited by hand.
- **Published standards (secondary, where they exist)**: IAPWS-IF97 release check tables for the
  IF97 engine; they validate independently of CoolProp.
- **Data fidelity**: generated Rust data compared field-by-field against the upstream JSON it came
  from — every number, not spot checks.
- **WASM size**: CI prints the release `.wasm` size per feature set each run. Size is a stated
  project goal; the report makes regressions visible (no hard gate until real numbers exist).

**Tolerance policy** (initial; revisit with evidence, log changes): Helmholtz-term-level
comparisons rel ≤ 1e-13; single-phase property values rel ≤ 1e-9; values behind iterative
saturation/flash solvers rel ≤ 1e-8; near-critical points get documented per-fixture overrides.
Bit-identity with C++ is not a target — libm implementations differ at ULP level and drift
compounds through Newton solvers. Error *conditions* must match upstream; exact message strings
are not a fidelity target.

## Phase 4 — HEOS engine, pure fluids

The largest phase. Order inside follows the upstream call chain: terms → props at (T,ρ) →
ancillaries → saturation → single-phase solvers → flash routines → all fluids.

- [x] 4.1 Helmholtz term evaluation, α⁰ and αʳ with all analytic derivatives upstream uses
      (∂/∂δ, ∂/∂τ up to the orders HEOS needs), for the term families Water uses.
      → verify: term-level goldens vs upstream Python `AbstractState` (`alphar`,
      `dalphar_dDelta`, `dalphar_dTau`, second derivatives, and α⁰ counterparts) on a (T,ρ) grid,
      rel ≤ 1e-13.
- [x] 4.2 Properties at given (T,ρ): p, u, h, s, cv, cp, w from the derivative matrix, exactly
      per upstream formulas.
      → verify: goldens vs upstream `DmassT_INPUTS` updates over the same grid, rel ≤ 1e-9.
- [x] 4.3 Ancillary equations (psat, ρ′, ρ″) and, where the fluid has one, the v8 Chebyshev
      superancillary evaluation.
      → verify: goldens vs upstream ancillary accessors across the saturation range.
- [x] 4.4 Pure-fluid saturation solver (ancillary-seeded, Maxwell criterion), matching upstream's
      iteration scheme.
      → verify: goldens for Q=0/Q=1 properties via `QT_INPUTS`/`PQ_INPUTS` across the dome,
      rel ≤ 1e-8; near-critical fixtures carry documented overrides.
- [x] 4.5 Single-phase density solver ρ(T,p) with upstream's phase determination.
      → verify: goldens vs `PT_INPUTS` over a grid covering liquid, vapor, and supercritical.
- [x] 4.6 Flash routines, one input pair at a time (each its own checkbox commit): (T,Q), (P,Q),
      (P,H), (P,S), (H,S), (D,T), (D,P) — including two-phase quality mixing. ((S,T) landed too,
      as the legacy HS path's inner solve.)
      → verify: per-pair golden grids that include two-phase states.
- [x] 4.7 Extend datagen + the full 4.1–4.6 test battery to five structurally diverse fluids:
      Nitrogen, CO2, R134a, Propane, Ammonia (covers Gaussian and non-analytic term families).
      Extend core types only as these files force it. (Done except the (H,S) pair, which is
      still open in 4.6 for all fluids.)
      → verify: all suites green per fluid; data fidelity tests green per fluid.
- [x] 4.8 Full sweep: datagen all active upstream fluids; per-fluid feature flags; coarse golden
      smoke grid for every fluid. Keep the default `cargo test` fast — the full sweep runs as an
      `--ignored` suite executed by a scheduled/manually-triggered CI job. (Scope: the 130 pure
      fluids, all of which have superancillaries; the 6 pseudo-pure fluids — Air, R404A, R407C,
      R410A, R507A, SES36 — need the pL/pV ancillary shape and the Maxwell saturation fallback
      and are deferred to a dedicated step.)
      → verify: all-fluids suite green; wasm size report now shows cost per single-fluid build.

**Phase gate 4**: any pure fluid, any supported input pair, HEOS parity with upstream.
